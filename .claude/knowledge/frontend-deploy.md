# Frontend Deploy

## Overview
Frontend is deployed to Azure Static Web Apps via GitHub Actions. Backend is a separate Azure App Service. The two are on different domains, which requires explicit CORS configuration and localStorage-based token storage (no cookies).

## Location
- `.github/workflows/` — frontend deploy workflow (Azure Static Web Apps auto-generated)
- `frontend/staticwebapp.config.json` — SPA fallback routing config
- `backend/BankOperations/Program.cs` — CORS policy configuration
- `frontend/.env.production` / GitHub secret `VITE_API_URL` — backend URL for production builds

## How it works

### Build and Deploy
1. GitHub Actions workflow triggers on push to `develop` with path filter `frontend/**`
2. Azure Static Web Apps uses **Oryx** to auto-detect the Vite project and build it
3. `VITE_API_URL` is injected as a GitHub secret — Oryx passes it as an environment variable during build
4. Built output is deployed directly to Azure Static Web Apps CDN

### SPA Routing
`staticwebapp.config.json` configures a navigation fallback so React Router handles all routes:
```json
{
  "navigationFallback": {
    "rewrite": "/index.html"
  }
}
```
Without this, direct navigation to `/login` or `/admin/dashboard` returns 404 from the CDN.

### CORS
Backend reads allowed origins from `ALLOWED_ORIGINS` env var (set in Azure App Service → Configuration → App Settings):
```csharp
var allowedOrigins = configuration["ALLOWED_ORIGINS"]?.Split(',') ?? [];
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
        policy.WithOrigins(allowedOrigins)
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials());
});
```
`ALLOWED_ORIGINS` value in Azure: `https://calm-pebble-0742a9a03.7.azurestaticapps.net`

### Cross-Domain Token Storage
Frontend and backend are on different domains (`azurestaticapps.net` vs `azurewebsites.net`). Browsers block cross-site cookies (SameSite=Lax default), so:
- Refresh token is returned in the response **body** (not HttpOnly cookie)
- Both `accessToken` and `refreshToken` stored in `localStorage`
- `AuthResultDto.RefreshToken` must NOT have `[JsonIgnore]`

## Key details
- **Do not add `skip_app_build: true`** to the workflow — Oryx must build the app to inject `VITE_API_URL` at build time
- **`VITE_API_URL` must be a GitHub secret**, not hardcoded — value is `https://bank-operations-api-hufubygyd7deg4ak.italynorth-01.azurewebsites.net`
- **`staticwebapp.config.json` must be in `frontend/`** (project root for the SWA deployment), not the repo root
- **`AllowCredentials()` is required** on the CORS policy even though cookies are not used — `fetch` with `credentials: 'include'` in `http.ts` requires it
- Local development uses `VITE_API_URL=http://localhost:8080` via `.env.development` or unset (falls back to `http://localhost:8080` in `http.ts`)

## Dependencies
- Azure Static Web Apps (free tier)
- Azure App Service (backend, existing)
- GitHub Actions — `Azure/static-web-apps-deploy@v1` action (auto-generated by Azure portal)

## How to extend

### Add a new environment variable to the frontend build
1. Add the secret to GitHub repository secrets
2. Reference it in the GitHub Actions workflow under `env:` in the build step
3. Use it in code as `import.meta.env.VITE_YOUR_VAR`

### Update the allowed origins
Update `ALLOWED_ORIGINS` in Azure App Service → Configuration → App Settings. Multiple origins: comma-separated string (`https://a.com,https://b.com`).

### Add a custom domain
1. Configure in Azure Static Web Apps → Custom domains
2. Add the new domain to `ALLOWED_ORIGINS` in the backend App Settings
